# Piwigo Internationalisation (i18n) Guide

Piwigo's translation system uses **gettext PO files** as its source format, backed by the `gettext/gettext` (parser) and `gettext/translator` (runtime) packages. The PHP array `.lang.php` files that existed in Piwigo ≤ 15 have been fully removed.

---

## File layout

```
language/
  en_UK/
    common.po      # user-facing strings (frontend + shared admin)
    admin.po       # admin-only strings
    install.po     # installer strings
    upgrade.po     # upgrader strings
    help_quick_search.po
    whats_new_15.po
    whats_new_16.po
```

Each file follows the standard [GNU PO format](https://www.gnu.org/software/gettext/manual/html_node/PO-Files.html).

---

## Adding a new translation key

1. Add the English string to the appropriate PO file in `language/en_UK/`:

   ```po
   msgid "My new feature"
   msgstr "My new feature"
   ```

2. If the string has singular/plural variants, use `msgid_plural`:

   ```po
   msgid "%d photo selected"
   msgid_plural "%d photos selected"
   msgstr[0] "%d photo selected"
   msgstr[1] "%d photos selected"
   ```

3. In PHP code, use `l10n()` for simple strings and `l10n_dec()` for plurals:

   ```php
   echo l10n('My new feature');
   echo l10n_dec('%d photo selected', '%d photos selected', $count);
   ```

4. Copy the new `msgid` to all other locale PO files with an empty `msgstr ""` so translators know what needs translating. The runtime falls back to the `msgid` when `msgstr` is empty.

## Plural forms

Every PO file header declares the locale's plural rule:

```po
"Plural-Forms: nplurals=2; plural=(n != 1);\n"
```

`l10n_dec()` uses `ngettext()` semantics and automatically applies the correct rule for the active locale. For example, Polish (3 forms), Arabic (6 forms), and Russian (3 forms) all resolve correctly without any code change.

The plural-form expression for each of the 72 bundled locales is in `tools/i18n/plural-forms.php`.

---

## Day and month names

Day names (`piwigo_day_0` … `piwigo_day_6`, 0 = Sunday) and month names (`piwigo_month_1` … `piwigo_month_12`) are stored as individual PO entries in `common.po`. After loading, the runtime rebuilds the legacy `$lang['day']` and `$lang['month']` arrays automatically so existing callers continue to work.

---

## Adding a new locale

1. Create `language/<locale>/` and add at minimum a `common.po` with the required PO header (see an existing locale for the template).
2. Add the locale's plural-form rule to `tools/i18n/plural-forms.php`.
3. Translate the strings. Empty `msgstr ""` values fall back to the English `msgid`.

## Conversion tools (`tools/i18n/`)

| Script | Purpose |
|--------|---------|
| `convert-all.php` | Batch-convert `.lang.php` → `.po` for the main language directory |
| `convert-ext-languages.php` | Same for the `piwigo16-languages` sibling repo |
| `verify-parity.php` | Assert every PHP key is present in the corresponding PO |
| `verify-parity-ext.php` | Same for the sibling repo |
| `extract-pairs.php` | Scan codebase for static `l10n_dec()` singular/plural pairs |
| `plural-forms.php` | Plural-form rule database for all 72 locales |
| `patch-day-month.php` | One-time tool to recover day/month arrays from git history |

## Runtime architecture

```
l10n('key')
  → Lang::t('key')
    → Translator::get()->translate('key')
      → Gettext\Translator::gettext('key')   # from loaded PO
      → fallback: $GLOBALS['lang']['key']     # plugins/themes without PO

l10n_dec('singular', 'plural', $n)
  → Translator::get()->plural('singular', 'plural', $n)
    → Gettext\Translator::ngettext(...)       # uses locale plural-form rule
```

`load_language()` tries `.po` first; if absent it falls back to PHP `include` (for plugins/themes that haven't migrated yet). The `$GLOBALS['lang']` array is kept in sync after every PO load so plugin/theme code that reads it directly continues to work.

Language switches (`switch_lang_to()` / `switch_lang_back()`) save and restore both the `LanguageStack` snapshot and the `Translator` singleton, so mail notifications sent in a recipient's language don't corrupt the active UI language.

## Crowdin / Weblate integration

PO is the native input format for all major translation platforms. Point your platform at the `language/` directory tree. The `en_UK` locale serves as the source (reference) language.
