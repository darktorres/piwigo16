# Modernize repository folder/file structure

## Context

The PHP, JS, and tooling have been heavily modernized on `16.x-rewrite` (PSR-4, PSR-15
controllers, DI container, PHPStan level 10, Vite build, TypeScript, Symfony components),
but the **filesystem layout is still the legacy Piwigo layout**: a flat project root
where source code, runtime data, configuration, vendor libraries, tests, install SQL,
and user uploads all live next to each other and are all directly reachable by HTTP.

This plan proposes a single, breaking restructure (no back-compat shims) with two
intertwined goals:

1. **Modern, conventional source layout** (Symfony-flavored).
2. **Server-agnostic web-root isolation**: the entire source folder lives outside the
   web root; only a tiny `public/` shim (generated by setup) is HTTP-reachable. No
   `.htaccess` rules, no DocumentRoot reconfiguration required. Works on Apache,
   Nginx, IIS, Caddy.

A second-order benefit: **private albums become actually private.** Originals are no
longer Apache-served from `galleries/`; they go through a PHP controller that enforces
permission checks before streaming the file.

---

## Current state — what's messy

1. **No web-root isolation.** `index.php` lives at the project root, so Apache serves
   the entire repo. There is **no `.htaccess`** anywhere. `vendor/`, `src/`, `config/`,
   `tools/`, `tests/`, `install/*.sql`, `composer.json`, `.env`, `_data/logs/` are
   all reachable via HTTP unless an external Apache rule blocks them. Single biggest
   defect.
2. **Originals served direct by Apache from `galleries/`.** Permission/album/user/group
   restrictions enforced by Piwigo are bypassed by any direct URL hit. URL obscurity is
   the only real protection.
3. **PHP and TypeScript share `src/`.** `src/Piwigo/` (PHP, PSR-4) mixed with
   `src/types/` (TS `.d.ts`).
4. **Frontend sources scattered across themes.** TS entries in `themes/_base/js/`,
   `themes/admin/_base/js/`, `themes/standard_pages/js/` — referenced from
   `vite.config.ts` and intermixed with templates, skin CSS, fonts, watermarks, icons.
5. **Underscore-prefixed legacy names.** `_data/`, `themes/_base/`, `themes/admin/_base/`.
6. **Working notes at the project root.** `e2e.txt`, `phpstan-l10.txt`,
   `plugins_list.md` (31 KB), `plugins_mgmt.md`, `INSTALL.md` belong in `docs/`.
7. **`dev/` and `build/` are near-empty.** Each holds 1–2 files that fit elsewhere.
8. **One-shot migration scripts in `tools/`.** Already-executed Python/PHP modernization
   scripts living next to live PHPStan extensions.
9. **`install/` SQL at the project root, web-reachable.**
10. **`template-extension/`** — legacy yoga/distributed overlay mechanism, mostly empty.
11. **STRUCTURE.md is out of date** — references `admin/`, `include/`, `i.php`,
    `action.php`, `qsearch.php`, all already removed.

## Proposed structure

### Two folders, two roles

**Source folder** (anywhere the user wants — `~/dev/piwigo/`, `/opt/piwigo/`, etc.) —
never web-served:

**Public shim** (created by setup at `<webroot>/<name>/`) — the only HTTP-reachable thing:

```text
<webroot>/piwigo/
├── index.php                     # Copied from public-template/; ~30 lines
├── .piwigo-paths.php             # Generated by setup — absolute path to source
└── dist/                         # Vite output (Vite outDir = absolute <public>/dist)
```

That's it. No `galleries/`, no `upload/`, no static theme assets, no SQL, no vendor.
`dist/` is the only directory in `public/` and contains nothing but built JS/CSS.

### Bootstrap files

**`public-template/index.php`** (committed, copied verbatim by setup):

```php
<?php
declare(strict_types=1);
$paths = require __DIR__ . '/.piwigo-paths.php';
require $paths['source'] . '/vendor/autoload.php';
\Piwigo\Bootstrap\HttpEntry::run($paths);
```

**`<public>/.piwigo-paths.php`** (generated by setup):

```php
<?php
return [
    'source'     => 'C:\\dev\\piwigo16',          // absolute path to source folder
    'public'     => __DIR__,                       // resolves at request time
    'url_prefix' => '/piwigo',                     // URL prefix used by UrlGenerator
];
```

**`local/config/paths.json`** (generated by setup; sidecar for build tools):

```json
{
  "public": "C:/Apache24/htdocs/piwigo",
  "url_prefix": "/piwigo"
}
```

`vite.config.ts` reads this at build time to set `outDir` to an absolute path inside
`<public>/dist/`. `npm run build` runs from source, writes straight to public.

### Originals served via PHP

`var/galleries/` and `var/derivatives/` are **never** HTTP-reachable. They are streamed
by PHP controllers that run permission checks first:

- Existing route `?/i/<...>` → `ImageDerivativeController` (already PHP-mediated).
- New/extended route `?/p/<id>/<...>` → original-file controller with the same
  fast-path bootstrap (config + logger + auth check, skip `Kernel::boot()`).
- HTTP cache headers (`ETag`, `Last-Modified`, `Cache-Control`) and 304 handling kept
  cheap; `Range:` requests supported for video.
- Optional `X-Sendfile` (Apache `mod_xsendfile`) / `X-Accel-Redirect` (Nginx) support
  for installs that want web-server byte delivery after the PHP auth check.

This is a strict security improvement over current Piwigo behavior.

### Setup script flow

`setup.ps1` / `setup.sh` extended:

```bash
setup.sh                                 # interactive
setup.sh --webroot /var/www/html --name piwigo    # non-interactive
```

Setup:

1. Prompts for web root path (validates exists + writable).
2. Prompts for public-folder name (validates target doesn't exist).
3. Creates `<webroot>/<name>/`, copies `public-template/index.php` into it,
   writes `<webroot>/<name>/.piwigo-paths.php` with absolute source path.
4. Writes `local/config/paths.json` (sidecar for Vite + any other build tooling).
5. Creates `<webroot>/<name>/dist/` (empty placeholder — populated by `npm run build`).
6. Composer install + npm install + npm run build (so `dist/` is populated immediately).
7. Prints next-step URL: `http://<host>/<name>/?/install`.

### Defaults chosen for residual decisions

- **`themes/` is dissolved entirely** into `resources/` (templates, frontend, skins).
  No top-level `themes/` directory remains. Future user themes ship as
  `plugins/<name>/` (themes are just plugins-with-templates).
- **`tools/*.py` migration scripts are deleted.** Already executed; git history is
  canonical.
- **No `--in-place` dev mode.** Setup always produces a separate `public/` shim, even
  for development. One supported deployment model. The dev workflow is to point setup
  at the local Apache htdocs once, then edit the source folder freely.

If any of these defaults are wrong I'd rather know now than after the migration runs.

## Migration steps (one commit each, tree runnable after each)

### Step 1 — Move runtime data: `_data/` → `var/`

- Rename directory.
- Update `Config::dataLocation()` in `src/Piwigo/Config/Config.php` and any callers
  hard-coding `_data/`. Update `.gitignore`.

### Step 2 — Fold `galleries/` and `upload/` into `var/`

- `galleries/` → `var/galleries/`. `upload/` → `var/upload/`.
- Update `Config::galleriesPath()`, `Config::uploadPath()`, plus any hard-coded
  references in `src/Piwigo/Admin/Upload/`, `src/Piwigo/Image/`, controllers.
- Update default site URL roots in `Config::SCHEMA`.

### Step 3 — New original-file controller

- Add `Piwigo\Controller\OriginalImageController` (or extend
  `ImageDerivativeController`).
- Wire route `?/p/<id>` (or chosen scheme) in `config/routes.php`.
- Use the same fast-path bootstrap pattern `index.php` already uses for `?/i/`.
- Permission check via existing `Piwigo\Permission\PermissionRepository`.
- Add tests in `tests/Integration/Controller/`.

### Step 4 — Rewrite all originals URLs

- `Piwigo\Url\UrlGenerator::originalUrl()` (new or existing) emits `?/p/...` URLs.
- Sweep templates (`{$src}` references) and any hard-coded `galleries/...` paths.

### Step 5 — Move tests fixtures + delete `dev/`

- `dev/fixtures/` → `tests/fixtures/`.
- Update `tests/bootstrap.php` and `playwright.config.ts`.

### Step 6 — Move build/ + delete one-shot scripts

- `build/piwigo-manifest-plugin.ts` → `tools/vite/piwigo-manifest-plugin.ts`.
- Delete `tools/*.py` and `tools/build-config-*.php`, `tools/migrate-*.php`,
  `tools/analyze-*.py`, `tools/fix-*.py`. Keep `tools/triggers_list.php` (still useful).

### Step 7 — Consolidate docs

- Move `INSTALL.md`, `plugins_list.md`, `plugins_mgmt.md`, `e2e.txt` (rename `.md`),
  `phpstan-l10.txt` (rename `.md` or delete) → `docs/`.

### Step 8 — Rename plugin-config namespace

- `src/Piwigo/Plugins/` → `src/Piwigo/PluginConfig/`.
- Sweep `use Piwigo\Plugins\…\Config;` → `use Piwigo\PluginConfig\…\Config;`.
- Update PHPStan paths.

### Step 9 — Split themes/ into resources/

The biggest single change.

- `themes/_base/template/` → `resources/templates/gallery/`
- `themes/_base/js/` → `resources/frontend/gallery/js/`
- `themes/_base/css/` → `resources/frontend/gallery/css/`
- `themes/_base/{s26,dark,light}/` → `resources/skins/gallery-{s26,dark,light}/`
- `themes/admin/_base/template/` → `resources/templates/admin/`
- `themes/admin/_base/{js,css}/` → `resources/frontend/admin/{js,css}/`
- `themes/admin/{light,dark}/` → `resources/skins/admin-{light,dark}/`
- `themes/standard_pages/template/` → `resources/templates/standard_pages/`
- `themes/standard_pages/js/` → `resources/frontend/standard_pages/`
- `template-extension/{yoga,distributed}/` → `resources/templates/overrides/`

Files updated:

- `vite.config.ts` — every input path; `outDir` becomes absolute (read from
  `local/config/paths.json`).
- `src/Piwigo/Template/Template.php` — Smarty template-dir search list.
- `src/Piwigo/Theme/Themes.php` — theme discovery.
- `src/Piwigo/Template/{ScriptLoader,CssLoader}.php` — asset path resolution
  (read from `<public>/dist/manifest.json`).
- Every `themeconf.inc.php` referencing `template/` paths.

### Step 10 — Move TS types out of src/

- `src/types/*.d.ts` → `resources/frontend/types/`.
- Update `tsconfig.json`.

### Step 11 — Move install SQL

- `install/{config.sql,piwigo_structure-mysql.sql,db/*,obsolete*.list}` →
  `resources/install-sql/`.
- Update `InstallController`, `UpgradeController`, `Admin/InstallService`.

### Step 12 — Move language/ to resources/

- `language/` → `resources/lang/`.
- Update `Piwigo\Lang\LangLoader`, `Piwigo\Admin\Languages`, `LANGUAGE_PATH`
  constants.

### Step 13 — Public shim + setup script extension

- Add `src/Piwigo/Bootstrap/HttpEntry.php` — entry called from generated
  `public/index.php`. Rolls up what current root `index.php` does (ConfigLoader,
  early-route detection for `?/i`, `?/install`, `?/upgrade`, `?/p`).
- Add `public-template/index.php` — committed, copied verbatim.
- Extend `setup.ps1` and `setup.sh` per the flow above.
- Delete root `index.php` (replaced by generated public shim).
- `Config::publicPath()` and `Config::sourcePath()` accessors read from the loaded
  `$paths` array; templates use these for emitting URLs.
- `vite.config.ts` reads `local/config/paths.json` for `outDir`.

### Step 14 — Update meta files + STRUCTURE.md

- `composer.json` (PSR-4 paths, `Piwigo\PluginConfig\` rename, autoload `files`).
- `phpstan.neon` (paths, excludePaths, bootstrapFiles).
- `phpunit.xml.dist` (testsuite directories).
- `rector.php` (`withPaths()`).
- `pint.json`, `eslint.config.ts` glob roots.
- Rewrite `docs/STRUCTURE.md`.

- `npm run typecheck && npm run lint && npm run lint:css`
- `npm run build` — Vite produces `<public>/dist/` with all expected entries.
- `npm run test:e2e` — Playwright e2e passes.
