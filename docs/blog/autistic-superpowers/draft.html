How I used my autistic superpowers to rewrite a legacy PHP codebase, 100k LOC

A first-person account of taking Piwigo from PHP 5.x and MySQL MyISAM to PHP 8.5, InnoDB, PostgreSQL and SQLite — told in numbers and pictures first, story second.

Part threeThe bet that isn't proven yet

The single number most likely to make someone keep reading: what running under a worker instead of a fresh process per request is expected to do to throughput.

Both numbers above are targets, not results — the same honesty rule the existing blog post's own "Benchmarks" section already follows (its harness exists; the numbers don't, yet). ~500 req/s is roughly what classic per-request PHP tops out at under mod_php/php-fpm for a dynamic app like this; ~60,000 req/s is in line with FrankenPHP's own published worker-mode numbers for comparable PHP applications — not a number this project has produced with its own load test. k6-load is already wired into CI (scaffolded since P3) but currently runs a stand-in step. Real numbers replace this whole section once that's real.

Why the gap should be that large, independent of the measured number: classic per-request PHP tears down and rebuilds the entire application — container, routes, config, DB connections — on every single request. A worker keeps all of that warm in memory between requests and only re-runs the actual handler. The second half of the bet is the image pipeline: swapping GD for libvips, which streams image data instead of decoding a whole bitmap into memory, so derivative generation is expected to land both faster and meaningfully lighter on RAM per conversion — no benchmark for that yet either, same rule applies.

Part fourThe story begins

Day zero: the exact commit the rewrite forked from, and the fork-in-the-road that almost went a different way.

Commit 54bdc4e21, April 26, 2026 — a routine security fix (GHSA-jhp4-7f82-8f6q, validating image_order against an allowlist) — turned out to be the last commit before any rewrite work touched this codebase. Phase 0 scaffolding started the same day.

Three weeks into the 16.x-rewrite effort, a second attempt started from the exact same baseline: 16.x-v2, with its own from-scratch Phase 0 — Composer, PHPStan, Psalm, Rector and Pint baselines; Vite, Vitest, ESLint and Stylelint — built independently rather than branched from the work already three weeks in. It ran for about 33 hours, ending with a run of commits fixing PHP 8 deprecation warnings and runtime errors the test suite surfaced, then stopped. 86 commits, never touched again.

Needs your input

The commit history shows that 16.x-v2 was abandoned in favor of continuing 16.x-rewrite, but not why — that call isn't in any commit message. This is the most human beat in the whole timeline (two approaches running in parallel, one survives after about a day) and it needs your own memory of that decision before this section is real.

On May 10, the surviving lineage bumped its own version string to 17.0.0 — a deliberate marker that every existing plugin and theme extension was about to be incompatible, not an accident of versioning. What's now this worktree, 17.x-rewrite-2, descends directly from that line: 14,795+ commits and counting, as of today.

Part fiveFoundation (P0–P4)

Five phases, and not one line of first-party application behavior changes in any of them. The entire job here is standing up the tools everything after gets held to.

PHP tooling first — Pest, PHPStan, Psalm, Rector, ECS, Deptrac, dependency and security-advisory scanners, a microbenchmark harness — recorded as baselines, not yet gating anything. Frontend tooling next, the same shape: Vite, TypeScript, ESLint, Stylelint, Vitest, bundle-size and dead-export checks. Then a real test harness (an isolated .env.test, a fixture database, browser and WS contract suites), a CI pipeline, and a containerized runtime with health checks and restore drills. Additive, on purpose — so phase five onward has a baseline to measure drift against instead of a guess.

Part sixPSR-4 & the architecture boundary (P5–P6)

The largest phase by commit count, followed by the one that decides what "layer" even means for the other 49.

A whole-codebase style fix, PHPStan's bleeding-edge rules applied file by file across the still-legacy tree, and six vendored libraries replaced or dropped outright — PHPMailer for Symfony Mailer, phpqrcode for a maintained package, the vendored Smarty copy for the real one, phpass for native password_hash(), among others. Then P6: every first-party class extracted out of procedural include/ and admin/include/ files into a real Piwigo\ namespace tree, and a six-layer architecture model defined and enforced from that day forward.

Caught & fixed

Deptrac silently breaks its own rule resolution when a layer name contains a hyphen — the original L0-Data-style names made every legal cross-layer dependency misreport as a violation. Fixed by dropping the hyphens from every layer name. Same lesson recurred twice more later in the project: when a tool's output looks structurally wrong, suspect the tool's model of the code before the code itself.

Caught & fixed

CsrfService was still hashing tokens with hash_hmac('md5', …) plus a plain === comparison long after the identical pattern had already been fixed in its sibling AuthService/EphemeralKeyService — the kind of drift that happens when a fix lands in one place and nobody checks for its twins. Part eightConfig, DB & language (P13–P16)

Where a real, silently-shipped security bug got found — not by a scanner, by reading why a migration had stalled.

A 277-entry typed config schema and loader; a Doctrine ORM layer under 38 domain repositories; a full schema migration to InnoDB and utf8mb4 with real foreign-key constraints and an audit log; and typed facades replacing 52 define() constants, alongside a full .po language migration with real ICU pluralization.

Caught & fixed

The $conf → typed-config migration had stalled at 72 files still reading the legacy global — not from an incomplete migration, but because the two were provably out of sync: ConfigService::loadConfFromDb() wrote a value into the legacy $conf global and never into the live config object at all. The concrete, shipped symptom: a CSRF service silently operating with an empty secret key. Fixed by making the DB write path update both.

Part nineThe service layer (P17–P23)

Where the legacy tree actually goes away.

Around 35 domain namespaces migrated across four dependency-ordered tiers — URL, session and permalink logic first, then mail, auth and tagging, then category and search, then page renderers last — each legacy include/ file deleted the moment its replacement landed, not batched to the end. 37 admin sub-controllers replaced the raw legacy admin/*.php file set; 19 of 21 planned frontend controllers were built, the two absences (Install, Upgrade) both deliberate — an installer can't go through a DI-resolved router before any DB exists, and there's no upgrade mechanism left in a clean fork to drive one. Then the close-out: include/ and admin/ deleted as directories, every $GLOBALS read and bare legacy free-function call gone from src/, each guarded by a zero-tolerance test.

Part tenPaying down what P23 couldn't finish (P24)

One nominal phase, 373 pages of plan text, because the tidy story the previous phase told about itself didn't hold.

P23 had promised zero global $x reads. The premise didn't survive contact with the real tree: around 230 files carried real, live global contracts the migration discipline had deliberately preserved verbatim rather than break. That debt, plus the DBAL-to-ORM remediation P14 never finished and a long tail of sweeps, became the real P24 — retargeting $template, $lang, $user, $conf and (hardest, nine sub-batches) $page onto real typed objects; retargeting 240 event call sites off three free functions and onto typed dispatch; a 74-commit campaign converting roughly 55 static-singleton classes to constructor-injected DI, motivated by worker-mode request isolation, not style; and removing the table-prefix mechanism entirely — 39 static methods, ~1,670 call sites inlined from a verified mapping, then deleted.

Caught & fixed

A dedicated bound-parameter sweep across the codebase turned up seven real, live SQL injections that had nothing to do with style: three in the image repository, one in comments, one spanning history and notifications, a plugin-hook injection point, and one more found in a same-day re-audit. All fixed as part of moving every raw SQL splice onto bound parameters. Mutation testing separately caught seven more bugs nothing else could see — a maintenance job reading the real wall clock instead of the injectable one tests can freeze, a URL builder appending a stray trailing colon nobody had ever noticed, a French pluralization file with a corrupted accented character sitting inside a regular expression.

Part elevenThe WS layer & REST (P25–P27)

The old plan had this as one phase — "REST layer, WS removed" — and it sat at "not started" for a long time because that framing was wrong.

A review found the legacy WS layer actually serves two different audiences through one surface: most of its 94 methods are internal admin plumbing exposed as a public contract, and only a third are the real machine surface anything external needs. That's why it split into three: modernize the legacy internals first without changing one wire byte, proven by a 604-test contract suite that never changed either; then ship /api/v1 — REST, OpenAPI 3.2, a generated TypeScript client, a real tus resumable-upload protocol — and delete the entire legacy WS layer in the same phase it goes live.

The P25 review found seven real security holes, fixed and shipped ahead of the modernization work itself: a global addslashes() corrupting data on every request; an API-key session that could be laundered into a full unrestricted session through the upload endpoint, making every API-key-forbidden method callable; an authenticated arbitrary-directory write via an unvalidated chunk-upload parameter; and WS's own copy of the CSRF check still comparing tokens with !== instead of hash_equals() — the same class of bug Part seven describes, just not caught by that earlier fix because it lived in a second, independent copy of the same logic.

Part twelveSecurity hardening (P28)

Not everything in this story is finished, and the honest way to show that is to say so plainly rather than skip the section.

Not started

WebAuthn/passkeys, OIDC SSO, a nonce-based Content-Security-Policy, COOP/COEP headers, and CSP violation reporting — none of it has landed. The clearest concrete marker: the rate_limiter cache pool, the one pool Part seven's cache work deliberately left unbuilt specifically as this phase's own scope, still doesn't exist. This is genuinely open work, not a modesty flourish.

Part thirteenPlugins, layering & the repo restructure (P29–P30)

A plugin contract designed from a real survey, not a guess at what plugin authors might want.

Every real plugin in the wild — roughly 400 extensions — and every real theme — 113 files — was read to ground the design in actual usage: 162 distinct legacy plugin events exist out there, and 11 of the top 12 by frequency already have a shipped, typed, 1:1 replacement event class. Layer decoupling closed out clean: the six-layer model from Part six enforces zero violations with no escape hatch, a live ratchet that has already caught and fixed two real regressions the same day they were introduced. The repository itself was restructured around a plain public/ sibling directory holding only real entry points — no PHP code directly web-reachable outside it.

Part fourteenLatte, and splitting the template god-object (P31–P44)

One number carries this whole part: 78% of the entire template tree was boilerplate, and it took until here to delete it.

Smarty→Latte migration first, 80 commits across all 139 real templates, the old engine retired outright. Then lint and format tooling built from scratch — no Prettier plugin for Latte existed anywhere, so one got hand-written, a real recursive-descent parser producing a typed AST. Then an idiomatic-modernization pass: 451 conditional/loop conversions across 91 templates, 1,009 escape-suppression sites individually classified by walking the AST, not grepped.

Then the largest single diff in the whole rewrite. Template — 1,370 lines, 36 public methods, one request-global bag every template read from — split into a one-method Renderer, a TemplateLocator, a typed ThemeChain, an asset seam, a typed contribution registry, and a trimmed extension class. Every template gets its own typed view object instead of an untyped bag, which deletes all 93,420 lines of repeated {varType} declarations along the way — 78% of the entire 119,752-line template tree, gone.

Caught & fixed

Extracting inline JavaScript out of templates surfaced a real, previously-shipped bug: plugins_installed.latte interpolated a raw PHP boolean directly into const isWebmaster = {$isWebmaster}; through a text escaper that doesn't quote booleans — for a non-webmaster admin that rendered as const isWebmaster = ;, a genuine JavaScript syntax error breaking the entire combined footer script bundle for exactly that audience, invisible until the extraction forced a real json_encode() through the new data-exposure mechanism instead.

Part fifteenThe frontend rewrite (P45–P51)

Same behavior, different language — .js becomes .ts, then jQuery leaves entirely.

A mechanical JS→TS conversion first, wiring 68 real Vite entries in place of a placeholder that had sat unused since Part five. Then real typing work: the page-data reader gets typed against Part fourteen's JSON island, and TypeScript's any escape hatch gets driven to zero across all of it — not a rename, real type design. Monolithic per-page scripts get broken into real ES modules. jQuery removal is a per-surface decision, not a blanket sweep — the vendored bundle, three separate widget libraries, and the installer's own separate copy each get evaluated and replaced independently; a small Lit component catalog exists only for the handful of widgets nothing vanilla replaces cleanly. Then a CSS architecture pass — container queries, cascade layers — proven against the same visual baselines the whole project already trusts.
