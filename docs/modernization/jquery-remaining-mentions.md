# jQuery — Remaining mentions audit

## Context

`jquery-removal.md` declared "Waves 1–6 complete. jQuery fully removed." That is correct for the authored TS / admin runtime path: every admin TS file is jQuery-free, every templated `{combine_script id="jquery"}` in the rendered page chain is gone, and `themes/default/js/jquery.min.js` no longer exists.

This document inventories every remaining textual mention of `jquery`, `jQuery`, `jqtree`, or a known jQuery-plugin name in the repo, so we know exactly what is residue, what is intentional, and what is still load-bearing.

Audit date: 2026-05-01. Branch: `16.x-rewrite`. Excludes `node_modules/`, `dist/`, `.git/`, `tests/test-debug/*.json` (autogenerated browser-coverage captures from pre-removal runs).

## Bucket 1 — Live runtime references that should be removed (stale residue)

These are functional code paths that still reference jQuery but no longer have a jQuery to find. Each is a small bug-fix-shaped commit.

| File | Line | Issue |
|---|---|---|
| `themes/standard_pages/template/header.tpl` | 24 | `{combine_script id="jquery" load="header"}` — Wave 6 said "all header templates" had this removed; this one was missed. `ScriptLoader::$known_paths` no longer maps `jquery`, so this either renders an empty/broken `<script>` tag or silently no-ops. Verify that `standard_pages` is not selected by any active theme before deleting; if it is unreachable, delete the whole template. |
| `themes/standard_pages/template/toaster.tpl` | 1 | `require='jquery'` on `combine_script` for `toaster_js`. The toaster module is jQuery-free; drop the require. |
| `dev/vite-entries.json` | 2, 45-53 | Top comment plus `vendored_ids` array list 22 legacy `jquery.*` ids ("jquery", "jquery.ui", "jquery.colorbox", "jquery.selectize", "jquery.ajaxmanager", "jquery.confirm", "jquery.tipTip", "jquery.cluetip", "jquery.cookie", "jquery.progressBar", "jquery.sort", "jquery.autogrow", "jquery.plupload", "jquery.plupload.queue", "jquery.ui.datepicker", "jquery.ui.timepicker-addon", "jtree", "plupload_i18n", …). `ScriptLoader::$known_paths` no longer contains any of them. The whole `vendored_ids` block is dead config — keep only the genuinely-still-vendored entries (`piecon`, `mcs` if still vendored, `jquery.geoip` only because the entry name persists in the manifest). |
| `tests/playwright.config.ts` | 31, 32, 40-42 | Coverage filter excludes `/themes/default/js/plugins/`, `/themes/default/js/ui/`, `jquery.js`, `jquery.min.js`, `jquery.cookie.js`. Those directories and files are deleted. Filter rules can never match — drop them. |
| `tests/e2e/base-test.ts` | 169, 170, 178-180 | Same dead filter rules as above (parallel definition). |

## Bucket 3 — Identifier carries the jQuery name but the implementation is jQuery-free

These would require a coordinated rename across PHP + every language file; pure cosmetic, no behavior change.

### `pwg_lang_info.jquery_code`

PHP-side per-locale field for the jQuery-UI locale code (e.g., `fr`, `pt-BR`, `zh-TW`). Used to derive `plupload_code` by `_-` swap. The field is now read by zero JS files but is still set by every translated language pack.

| File | Lines | Role |
|---|---|---|
| `src/types/globals.d.ts` | 10 | TS ambient declaration of `pwg_lang_info` shape |
| `src/Piwigo/Template/Template.php` | 158-163 | Default-fills `jquery_code` from `code`, derives `plupload_code` from `jquery_code` |
| `language/zh_TW/common.lang.php` | 21 | `$lang_info['jquery_code'] = 'zh-TW';` |
| `language/zh_CN/common.lang.php` | 21 | `$lang_info['jquery_code'] = "zh-CN";` |
| `language/ko_KR/common.lang.php` | 20 | `$lang_info['jquery_code'] = "ko";` |
| `language/sh_RS/common.lang.php` | 21 | `$lang_info['jquery_code'] = 'sr-SR';` |
| `language/uk_UA/common.lang.php` | 21 | `$lang_info['jquery_code'] = "uk";` |
| `language/pt_BR/common.lang.php` | 21 | `$lang_info['jquery_code'] = 'pt-BR';` |

Decision: defer. A clean rename to `ui_locale_code` (plus shim period for plugins reading the old key) belongs in the broader modernization plan's "globals → typed services" phase. Not worth a one-off churn commit.

### `admin/themes/default/js/jquery.geoip.ts` + entry name `jquery.geoip`

## Bucket 7 — Build-system noise (unavoidable)

| File | Lines | Notes |
|---|---|---|
| `package-lock.json` | 1095, 1194-1198 | `node_modules/jquery@4.0.0` is installed because `datatables.net@2.3.8` declares `"jquery": ">=1.7"` as a runtime dependency. We use DataTables in vanilla mode, so jQuery is never imported, never bundled, never shipped — but npm still resolves it into the lockfile. Could potentially be eliminated by switching to `datatables.net-dt` or by adding an `overrides` entry, but the cost is fragility on next datatables upgrade for zero runtime benefit. |

Decision: accept. Lockfile-only artifact; bundles do not contain jQuery.

## Suggested cleanup order

1. **Bucket 1** in one commit: drop the dead `combine_script` in `standard_pages/header.tpl`, `toaster.tpl`'s `require='jquery'`, the dead `vendored_ids` block in `dev/vite-entries.json`, and the dead Playwright filter rules. Pure deletion, no behavior change.
2. **Bucket 4** as part of any future theme.css audit.
3. **Bucket 3** during the broader globals→services phase.
4. Buckets 2, 5, 6, 7 — leave alone.
